## 4. 未采纳的建议

**"brief/full 都设上限并声明裁剪量"。** 只对**散文块**截断（600 字 + 标注截断字符数），
**没有**给参数表设总量预算：`rodCreatePath` brief 仍有 35,266 字（62 个参数），但那是官方
文档本身的体量。截断参数表会直接造成"照返回写代码却缺参数"的坏调用，与工具层"宁可长、
不可缺"的取舍原则相反。若审计方仍希望有总量上限，建议以**显式预算 + 裁剪标注**（不静默）
的形式提出具体阈值，我们再评估。

## 7. 已知残留（如实列出）

1. **参考链接**：正文是散文、或正文里逗号连写的名字与链接文本不一致时（如链接文本写作
   `cont, continue`），同一批函数名仍可能在**同一行**内出现两次。这是官方原文的冗余，
   不做词级替换以免改动散文。全库 162 个函数的 `相关:` 行里存在"某个标识符在行内出现
   ≥2 次"的情形——其中一部分是**正文散文里提到了同名函数**（如 `arrayref` 的正文
   "…referred to as the setarray function." 与链接 `setarray`），属正常表达而非重复罗列。
2. **`rodCreatePath` 等大函数 brief 仍 35k 字**：见 §4，属官方文档体量，非策略缺陷。
3. **`option_descriptions` 在 brief 档只给指针**：若希望 brief 直接给选项说明的**前 N 条**，
   可提出阈值，这是策略表一行改动、零重建。
4. **解析层**：`deOpen`(6,737 字)、`procedure`(3,710)、`techSetMPPTemplate`(2,197)、
   `hiHelp`(1,866)、`simInitEnvWithArgs`(1,600) 等纯散文块**不做条目化**——硬切会造出
   `For` / `Note:` 这类假参数名；这些内容以"条目之外正文"的形式投送。

## 8. v0.1.9：对复核结论的处置（2026-10-10）

对复核提出的三点逐一核实后落地，**已打标签并推送 v0.1.9**。复核中"全库 12 个数字全部复现、
仅一处口径错误由复核方自查"的情况我们也确认；本节只记改动。

| 复核项 | 处置 |
|---|---|
| **B3 只修一半**：full 里仍输出 `解析状态: {"example": "unparsed"}`（134 个函数），与人话标题并存 | 改为中文措辞、不再暴露内部字段名与枚举值（`解析状态: 声明取自共享主题`、`解析状态: 示例节官方原文未能可靠提取`）；已由正文块标题写明状态的 `参数`/`返回值` 两节**不再重复列** |
| **B4 跨页漏网**：`nconc(list.html#1039401)` 这类跨页链接把锚点粘在函数名后（实测 263 处 / 155 个函数，含数字锚点 197 处、符号锚点 66 处） | href 统一去掉 `#…`：跨页保留文件名 `nconc(list.html)`，页内只留名字；配合原有的同名去重 |
| **§3 brief 预算**：提议"首行 + 取值/Default 保留，长散文移 full，−44%" | **接受机制，并补两条**：① 由**参数块预算**（12,000 字）触发，实测只影响 **4 个函数**——`rodCreatePath` 35,266→25,069、`rodCreateRect` 28,913→17,368、`hiCreateAppForm` 16,593→5,714、`hiCreateReportField` 15,366→6,563；`hnlInitMap` 这类密集参数表**不触发**、原样保留。② 块尾**显式标注**：`（已把 26 个参数的说明续文移到 detail="full"，共 11,489 字；参数名、允许取值与 Default 均完整保留（保留行 2,254 字））` |

**为什么 §3 的标注不可省**：复核的论证是"一个参数名、一个允许取值、一个默认值都不会丢"。这条
我们逐函数核过，成立（`Default`/`Valid Values`/`取值` 计数一个不少）。但续行里 **82% 的行不是
取值/默认值，而是约束类文字**——`The value of x_displayOrder must be an integer…`、
`Note: This argument only applies to type-in fields.`、`Callback parameter list: (o_session r_form r_field)`。
这些正是"缺了就写错"的那一类，所以 brief 必须写明"说明被移到 full 了"，而不是静默截断。
